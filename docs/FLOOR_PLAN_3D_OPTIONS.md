# Floor Plan — แนวทางทำมุมมอง 3D (แผนอนาคต)

> **สถานะ: ยังไม่เริ่มทำ — เป็นบันทึกการคุยไว้ก่อน**
> คุยกันเมื่อ 2026-09-09 · ยังไม่ได้ตัดสินใจเลือกทาง · ยังไม่มีโค้ดใด ๆ ถูกแก้
>
> เอกสารนี้เขียนไว้ให้คนที่กลับมาอ่านทีหลัง (รวมถึงตัวเราเอง) หยิบไปทำต่อได้เลย
> โดยไม่ต้องไปไล่สำรวจ schema ใหม่

---

## สรุปสั้น

**ทำได้ และข้อมูลพร้อมกว่าที่คิด** — ชั้นวาง (Rack) กับช่องเก็บของ (Bin) ขึ้น 3D ได้
โดย **ไม่ต้องแก้ฐานข้อมูลเลย** เพราะความสูงคำนวณจาก `Slot.level` ได้อยู่แล้ว

สิ่งที่ต้องเพิ่มคือความสูงของ *พื้นที่อื่น* (Receiving / QC / กำแพง) ซึ่งยังไม่มีข้อมูล

---

## 1. ข้อมูลที่มีอยู่แล้ว (ตรวจกับ schema จริงเมื่อ 2026-09-09)

| ต้องการอะไรใน 3D | มีอยู่แล้ว | อยู่ที่ไหน |
|---|---|---|
| ตำแหน่งบนพื้น (x, y) | ✅ | `LayoutObject.x`, `.y` |
| ขนาดฐาน (กว้าง × ลึก) | ✅ | `LayoutObject.width`, `.height` |
| การหมุน | ✅ | `LayoutObject.rotation` |
| ลำดับการซ้อน | ✅ | `LayoutObject.zIndex` |
| **ชั้นที่เท่าไหร่ (ความสูง)** | ✅ | `Slot.level` + `Rack.levels` |
| **ตำแหน่งซ้าย-ขวาในชั้น** | ✅ | `Slot.column` + `Rack.columns` |
| **ขนาดจริงเป็นเซนติเมตร** | ✅ | `Slot.lengthCm`, `.widthCm`, `.heightCm` |
| สี/ความแน่นของแต่ละช่อง | ✅ | `GET /api/warehouse-layout/:warehouseId/occupancy` |

**หมายเหตุ:** `Slot.lengthCm / widthCm / heightCm` มาจากงาน box-fit ของ Putaway
— มีมาก่อนเรื่อง Floor Plan และไม่ได้ทำเผื่อ 3D แต่ใช้ได้พอดี
(ระวัง: เป็น nullable — ของจริงอาจไม่ได้กรอกไว้ทุกช่อง ต้องมีค่า default)

## 2. สิ่งที่ยังขาด

- **พื้นที่ที่ไม่ใช่ชั้นวางไม่มีความสูง** — `LayoutObject` มีแค่ฐาน (x, y, width, height)
  ไม่มี `elevation` (สูงจากพื้นเท่าไหร่) และไม่มีความสูงของตัววัตถุ
  → ถ้าจะทำ ต้อง **เพิ่มคอลัมน์ใหม่** เช่น `elevation`, `heightUnits`
  (เป็นการเพิ่มคอลัมน์ ไม่ใช่แก้ของเดิม — ทำแบบ additive ได้เหมือน Sprint 2)
- **ยังไม่มี 3D library** ในโปรเจกต์

---

## 3. ทางเลือก 3 แบบ

### ทางเลือก A — Isometric 2.5D (ถูกที่สุด)

เอียงผัง 2D ที่มีอยู่ให้เป็นมุมเฉียง แล้ววาดชั้นซ้อนขึ้นไป

- ใช้ SVG เดิมทั้งหมด **ไม่ต้องลง dependency ใหม่**
- คลิกเลือกวัตถุได้เหมือนเดิม (ยังเป็น DOM node)
- โค้ดที่มีอยู่แล้วเกือบทั้งหมดใช้ต่อได้ — เปลี่ยนแค่วิธี project พิกัด
- **ข้อจำกัด:** ล็อกมุมกล้อง หมุนดูรอบ ๆ ไม่ได้

### ทางเลือก B — Three.js / react-three-fiber (3D จริง)

- หมุน / ซูม / เดินดูได้เต็มรูปแบบ
- **ต้นทุน:** bundle เพิ่ม ~600KB (ตอนนี้ทั้งแอปยังเบามาก)
- งานเยอะกว่ามาก: กล้อง, แสง, raycasting เพื่อคลิกเลือก, ป้ายชื่อที่ต้องหันเข้าหากล้อง,
  การ dispose object ตอน unmount
- ต้องคิดเรื่อง performance บนแท็บเล็ตในคลัง

### ทางเลือก C — Rack Elevation View (ไม่ใช่ 3D แต่อาจตอบโจทย์กว่า)

มองชั้นวางจากด้านหน้าเป็น 2D: **แถว = level, คอลัมน์ = column**, ใส่สีตามความแน่น

- ตอบคำถาม *"ของอยู่ชั้นไหน"* ได้ทันที
- **ข้อมูลมีครบแล้ว 100%** ไม่ต้องเพิ่มคอลัมน์อะไรเลย
- ทำได้เร็วที่สุดในสามทาง
- ใช้ `/occupancy` เดิมได้ตรง ๆ

### เทียบกัน

| | A · Isometric | B · Three.js | C · Elevation |
|---|---|---|---|
| ต้องเพิ่ม dependency | ไม่ | ~600KB | ไม่ |
| ต้องแก้ schema | เฉพาะถ้าอยากได้ความสูงพื้นที่อื่น | เหมือน A | **ไม่ต้องเลย** |
| หมุนกล้องได้ | ไม่ | ได้ | ไม่เกี่ยว |
| แรงงาน | กลาง | สูง | ต่ำ |
| ใช้โค้ดเดิมต่อ | เกือบหมด | น้อย | ปานกลาง |

## 4. ข้อควรระวัง (สำคัญ — อย่าข้าม)

**3D อาจไม่ดีกว่า 2D สำหรับงาน monitor**

- **ของบังกัน** — ชั้นหน้าบังชั้นหลัง ต้องหมุนกล้องหาตลอด ซึ่งช้ากว่าดูแผนที่แบน ๆ
- **คลิกยาก** — เลือกช่องเล็ก ๆ ใน 3D ยากกว่า 2D มาก โดยเฉพาะบนจอสัมผัส
- **แท็บเล็ตในคลังอาจหนืด** — WebGL กินทรัพยากรกว่า SVG เยอะ

**3D ดีกว่าจริงตอน:** สอนงานคนใหม่ให้เห็นภาพคลัง · นำเสนอผู้บริหาร · คลังที่ซ้อนหลายชั้นสูง

## 7. เรื่องอื่นที่ค้างอยู่ (ไม่เกี่ยว 3D แต่ควรทำก่อน)

จากที่คุยกันไว้ก่อนหน้านี้:

1. **ยังไม่เคยตรวจเลข `Available` / `Committed` กับข้อมูลจริง** — คำนวณจากการจัดกลุ่ม
   `StockStatus` เพราะ schema ไม่มีคอลัมน์นี้ ควรเทียบกับแท็บ Control Center ของช่องเดียวกัน
2. **ผังไม่ sync โครงสร้างอัตโนมัติ** — เพิ่ม Rack ใหม่แล้วต้องมาวาดเอง
3. **ไม่มีไฟบอกว่าข้อมูลสดหรือค้าง** บนหน้าจอ
4. **สั่งงานจากผังไม่ได้** — ดูอย่างเดียว
